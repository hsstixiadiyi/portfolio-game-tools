# 03 · 最小 Agent 工作流 Demo

> 方向：任务拆解 · 工具调用 · 流程编排 · 状态跟踪　|　技术栈：Python

## 背景与目标

- 解决什么问题：接收一句自然语言需求，自动拆成步骤，依次调用工具，跟踪执行状态并汇总结果。
- 对应岗位工作：Agent 与智能工作流能力建设（任务拆解、工具调用、流程编排、状态跟踪、结果反馈）

## 需求拆解

1. 定义输入需求的解析方式与任务数据结构：用关键词规则把句子拆成有序步骤列表。
2. 实现任务拆解，生成有序步骤列表（读取 / 词频统计 / 大写转换 / 写入）。
3. 封装可调用工具，统一输入输出接口：`{"ok", "data", "error"}`，便于扩展新工具。
4. 实现流程编排、执行状态跟踪与结果汇总反馈：逐步记录 running / success / failed，失败即中止。

## 技术栈

- 语言：Python 3（仅标准库）
- 工具调用：自研真实工具函数（`src/tools.py`），规则驱动拆解，不依赖大模型 API
- 配置：[config/tools.json](config/tools.json) 中登记工具名称、关键词与启用状态

## 实现要点

- 任务拆解：`plan()` 按逗号、句号等切分语句，用关键词匹配映射到工具调用，生成步骤列表；`config/tools.json` 中禁用的工具不参与拆解。
- 工具抽象：`call_tool()` 按名称查表调用，统一返回 ok / data / error；参数不匹配或运行时异常都被收敛为错误返回，不抛出中断。
- 流程编排：步骤顺序执行，上一步 `data` 作为下一步的文本输入（`write_file` 则作为 content）。
- 状态跟踪：每步记录状态、起止时间与错误信息；任一步失败即停止，并以非 0 退出码返回。

## 演示

- 运行方式：

```bash
python src/agent.py \
  --task "读取 examples/input.txt，统计词频，写入 demo/word_count.txt" \
  --log demo/run_log.txt
```

- 运行日志：[demo/run_log.txt](demo/run_log.txt)，逐步记录拆解结果与每步状态。

- 示例：输入「读取 examples/input.txt，统计词频，写入 demo/word_count.txt」→ 拆解为 `read_file → count_words → write_file` 三步 → 三步均成功 → 结果文件见 [demo/word_count.txt](demo/word_count.txt)。

## 遇到的问题与解决

- 问题 1：自然语言表述多样，规则拆解容易漏步骤 → 排查思路：先限定可识别语句范围（读取 / 统计词频 / 转大写 / 写入）→ 解决方式：在 README 与配置中明确支持的关键词，无法识别时直接提示而不是静默跳过。
- 问题 2：上游失败后下游工具仍会用空数据继续执行 → 排查思路：`context` 为空时 `count_words` 等工具会误处理空串 → 解决方式：执行器在下游步骤检查 `context`，为空则标记失败并中止整条工作流。

## 收获与可改进

- 收获：理解了 Agent 工作流中「拆解—调用—跟踪—汇总」四层职责的划分，以及统一工具接口对扩展性的意义。
- 可改进：接入大模型做更灵活的任务拆解；增加并发执行、失败重试与超时控制；接入真实 AIGC / 图像处理接口替换本地工具。
