# 02 · 节点式工作流画布

> 方向：可视化编辑器 · 复杂前端应用　|　技术栈：React、TypeScript、Vite

## 背景与目标

- 解决什么问题：做一个简化版节点编辑器，支持节点创建、拖拽、连线、属性配置与运行状态展示，用于编排一条可执行的工作流。
- 对应岗位工作：画布功能开发（节点与连线、资产预览、任务状态、工作流编辑、智能助手交互）

## 需求拆解

1. 定义节点类型（输入 / 处理 / 输出）与数据结构 `WorkflowNode`、`WorkflowEdge`。
2. 实现画布拖拽、节点渲染与端口连线交互。
3. 实现右侧属性面板与节点参数编辑，修改实时回写到节点数据。
4. 实现工作流运行状态（待运行 / 运行中 / 完成 / 失败）展示，并按拓扑顺序执行。

## 技术栈

- 框架：React 18
- 语言：TypeScript 5
- 画布方案：自研 SVG 连线层 + 绝对定位 HTML 节点，未引入第三方画布库
- 状态管理：React `useState` + `useRef`

## 实现要点

- 节点与连线数据模型：`WorkflowNode` 记录类型、标题、坐标、参数、状态与输出；`WorkflowEdge` 记录起止节点 id。
- 交互逻辑：节点标题栏用 Pointer Events + `setPointerCapture` 实现拖拽；点击输出端口再点击输入端口完成连线；画布提供「清空连线」「导出 / 导入 JSON」。
- 属性面板与状态同步：选中节点后，名称、输入文本、处理操作（转大写 / 加前缀 / 反转字符）的修改通过 `patchNode()` 回写到节点数组，画布即时刷新。
- 工作流状态跟踪：`topoOrder()` 做拓扑排序检测环路；运行时按序把节点切到 `running`，计算输出后切到 `done`，每个节点间隔 420ms 以便观察状态流转。

## 演示

- 本地运行：

```bash
npm install
npm run dev
```

打开 `http://localhost:5173`。构建检查：`npm run build`。

- 界面截图：[demo/canvas-screenshot.png](demo/canvas-screenshot.png)（本地预览的真实浏览器截图，展示默认三节点工作流与属性面板）。
- 可演示流程：默认已放置「输入文本 → 文本处理 → 输出结果」三个节点并连好线 → 点击「运行工作流」→ 观察节点状态从待运行变为运行中、完成 → 右侧显示最终结果；也可新增节点、改参数、连线、导出 JSON 后重新导入。

## 遇到的问题与解决

- 问题 1：拖动节点时误触发画布空白区点击，导致选中状态被清空 → 排查思路：事件冒泡到画布的 `onPointerDown` → 解决方式：在节点 `onPointerDown` 中 `stopPropagation()`，端口同样阻止冒泡。
- 问题 2：存在环路时工作流会卡住 → 排查思路：拓扑排序无法覆盖全部节点 → 解决方式：比较排序结果与节点总数，不一致时提示「检测到环路」并停止执行。

## 收获与可改进

- 收获：理解了节点编辑器的数据模型与交互拆分，掌握了用拓扑排序驱动状态流转、以及用受控组件保持面板与画布同步的方法。
- 可改进：加入缩放与小地图、节点类型校验、分支条件节点、异步任务真实执行与失败重试、资产预览面板。
